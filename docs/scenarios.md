# RideOps MVP 业务场景边界

本阶段先固定两个共享出行业务场景，优先完成事故场景的端到端闭环。

## 场景一：出行前

用户在开始用车前，希望完成：

1. 查询附近可用车辆
2. 路线和费用预估
3. 预约车辆

当前状态：仅固定业务边界和后续接口，不进入本轮实现。后续需要补充车辆位置、路线距离、计价规则和预约状态模型。

## 场景二：事故中

用户报告车辆事故、受伤、车辆损坏或订单仍在计费时，系统完成：

```text
收集信息
→ 查询订单和车辆
→ 检索事故政策
→ 信息不足时追问
→ 生成待执行动作
→ 人工审批
→ 写入订单/车辆/事故工单
→ 只读回读最终状态
```

当前 MVP 已完成该闭环的合成数据版本：

- SQLite 持久化订单、车辆、工单和 Run 状态
- 普通业务工具，不使用 MCP
- 简单 LangGraph 准备图和执行图
- 审批前不产生写入
- 批准后执行三个幂等写动作
- 拒绝后安全结束
- 重复 Resume 不重复产生副作用
- 前端通过普通 HTTP 请求展示真实 Run 状态

当前仍未实现：真实模型调用、FastMCP、复杂 Checkpoint、SSE、真实企业系统和 Redis。
